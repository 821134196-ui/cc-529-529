# 后厨刀具管控台（knifectl）

按刀具编号登记刀型、工位、领用人、刃口状态与磨刀周期；班次开始领刀、结束逐件清洗核对归还；
磨刀后由**另一个人**复检锋利度与刀身完整性。纯 Python 标准库实现（SQLite + http.server），
无需安装任何依赖。

## 一条命令启动

```bash
./run.sh            # 默认端口 8077，自动重建带「刃口缺口」等案例的数据库
./run.sh 9000       # 指定端口
```

打开 http://127.0.0.1:8077

页面：

| 路径 | 功能 |
|---|---|
| `/` | 工位刀架图（架/排/列真实槽位；刀型 = SVG 轮廓 + 文字双表示） |
| `/scan` | 领还扫码台：顶部突出缺件/未复检；右侧模拟扫码枪 |
| `/maintenance` | 保养排程：磨刀周期、超期、送磨、待复检 |
| `/quarantine` | 异常隔离：缺口/松动/错放/待修/遗失分区处理 |
| `/trace?id=K-001` | 逐刀流转时间线、刃口照片、最后接触人 |

## 业务规则（均在 `knifectl/service.py`）

- **独占领用**：条件 `UPDATE ... WHERE status='in_rack'` 原子占位，同一把刀不能同时被两名厨师领用。
- **发放闸门**：待修、遗失、隔离中、刃口缺口、磨刀超期、磨刀后未复检 —— 每种都有独立错误码与处理流。
- **归还核对**：清洗完好必须扫入归属槽位；扫错槽位 → 错放工位隔离 → 核对归位；
  刃钝送磨；刀柄松动/刃口缺口进隔离并分流送修。
- **复检权限**：磨刀者不能批准自己的复检（维修人、找回登记人同理），必须换复检岗；
  不合格退回隔离/维修。
- **遗失冻结**：遗失即冻结；找回先进「找回待检」隔离，复检完整性通过后才解冻回架。
- **班次跨日**：收班逐件核对，有未还/未交接刀一律拒绝；跨午夜的班次收班时单独标注 `cross_day`；
  跨班交接保持刀处于「领用中」，持用人唯一并落到新班次。
- **可追溯**：每次动作写 `events` 并刷新 `last_touched_by/at`。

## 组件

- `knifectl/db.py` — SQLite 建表（staff / stations / slots / knives / shifts / events / photos）
- `knifectl/scanner.py` — 模拟扫码枪适配器（线程安全事件队列，`/api/scan/emit`、`/api/scan/drain`）
- `knifectl/reminders.py` — 进程内提醒（后台线程：超期、将到期、待复检、隔离、跨日未还）
- `knifectl/photos.py` — 刃口照片本地存储（含纯标准库 PNG 合成，缺口用安全黄/红标出）
- `knifectl/seed.py` — 演示案例：缺口（K-003）、松动（K-004）、错放（K-008）、
  遗失（K-006）、待修（K-009）、磨刀超期（K-002）、待复检（K-005）、找回待检（K-012）、
  跨日未交接（K-007）、即将到期（K-010）
- `knifectl/web.py` / `ui.py` — HTTP 服务与界面（不锈钢白 / 炭灰 / 安全黄）

## 测试

```bash
python3 -m unittest tests.test_knifectl -v
```

20 个用例，重点覆盖：8 线程并发领同一把刀恰有 1 人成功、跨日班次收班与跨班交接、
磨刀/维修/找回三类自批复检拦截、遗失冻结到找回复检全流程。
